# Publisher monetary quality

An adopter may declare `appetite.publisher_reliability`, with one closed
`publisher-reliability/adopter-policy-v1` policy per inherited target feed.
Each policy explicitly selects a signed NIST report, publisher profile and
widening declaration, monetary unit, positive minimum case count and
nonpositive acceptance bar. No production policy or numerical default is
provided by the compiler. `appetite.pricing_threshold` remains the separate
evidence-grade threshold.

The initial admitted measure is `money-empirical-crps/v1`: the signed empirical
distribution of the declared annual monetary outcome is scored by negative
mean CRPS. Higher scores are better. The consumer compares exact rational
scores to the exact decimal bar; equality does not trigger. A valid empty or
insufficient population creates no score-trigger or claim of accepted quality.
An independently authenticated degraded native publisher release remains a
separate cause; either cause selects the same complete publisher target once.

`compose()` authenticates original canonical source tags, identities, exact
tree files and served Git history, then executes the selected NIST source's
report checker against the captured source closure. The checker reconstructs
the forecast/resolution population and actual pinned FAIR generation relation.
A report dictionary, asserted receipt, payload copy or cached score has no
admission authority. Missing, malformed or unauthenticated declared inputs
refuse by name; they do not become an empty population or a zero price.
Registration history retains its stated limitation: Git committer times are
publisher assertions, not independently observed wall-clock times.

The actual current feed and converter bytes must match the report's signed
target. Its native release-cage record binds the publisher's real gate code,
native evidence, version, bump and tier; the consumer replays that gate's
public verification operation. The pure publisher gate does not establish
cryptographic admission: the consumer also authenticates every captured prior
release's original tag, canonical signer/issuer and exact tree blob, checks its
captured tag object, and requires the chosen predecessor to belong to that
authenticated history. An annotated tag alone supplies no signature authority.
The publisher's `widen-to` CLI receives its
unaltered authoritative payload and current adopter context, and supplies the
full conservative scenario. Frequency and source arrangement remain fixed;
supported PERT loss magnitudes cannot narrow. Existing cage selection, FX,
open-control share, per-customer presentation and final selection still price
the resulting scenario. Actual uncaged amount and selected tier cannot become
looser under the widening. Post-cage retained cost may decrease when the
selected cage becomes stricter.

`prices[].publisher_reliability_effect` records the current-context base and
effective scenario, amount and tier, exact score/bar, population and causes.
Legacy `old_price`/`new_price` fields continue to compare publisher versions
under current adopter inputs. A policy for the current exact target version
does not silently apply to a different old publisher version. The rendered
handbook keeps these comparisons separate.

Only after complete admission is the report edge diagnostic: its publication
time and its own subscription `since` are excluded from financial date
selection. The financial date remains a date, and the evidence cutoff is
recorded separately as a UTC instant. A diagnostic report adds no exposure,
supersede or switching-cost line. With no declared policy, this feature adds
no effect marker and does not change legacy calculations or rendered files.

Fresh policy authoring uses the exact current `party.yaml` Git blob as a
same-tree context; it asserts no nonexistent future signed tag. The eventual
composed artefact's enclosing signature supplies its authority. Historical
forecast contexts remain exact signed external references. Saved composition
verification reconstructs original source stores from
`composed/publisher-reliability/sources.json` and rechecks original tag
certificates and report/native-gate computations offline. A payload/converter
copy alone cannot substitute for that closure. The surrounding saved-artefact
verification must authenticate the adopter's enclosing signed source.

The CLI's `--estate-clone` directory must also carry full canonical checkouts
for the exact resolver and historical context sources named by the report.
They need not be exposure subscriptions: monetary admission discovers them
separately, and does not make their FX converters or feeds pricing parents.
The Python seam may supply the same source locations through
`ParentTrees.monetary_sources`; every selected reference is still authenticated.

The optional monetary checker requires Python's `jsonschema` package in
addition to the existing PyYAML dependency; Git and offline `gitsign` are
required for nonempty source admission. Missing checker dependencies cause a
named missing-instrument refusal. No dependency import or source admission is
performed for an absent feature. The pinned FAIR engine remains the existing
pure-stdlib implementation; no new simulation engine is introduced.
